# code-diff — правила, которые нельзя «переинтерпретировать»

## Рабочий протокол (обязателен, важнее любых правил ниже)

1. МИНИМАЛЬНЫЙ ДИФФ: правится ровно то место, на которое указал пользователь.
   Всё, что шире, — сначала вопрос и явное «да». Никаких «заодно перепишу».
2. СНАЧАЛА КАРТИНКА: визуальное изменение → сборка → браузер → скриншот/DOM
   пользователю → «так?». Продолжать только после подтверждения. Не объявлять
   готово до этого.
3. СЛОВА ПОЛЬЗОВАТЕЛЯ = СПЕЦИФИКАЦИЯ дословно. «Порванная лента вот тут» =
   склеить ЭТУ ленту, не «удалить все заливки». Шире — только через вопрос.
4. Тесты закрепляют ПОДТВЕРЖДЁННОЕ пользователем поведение, не мою трактовку.
5. Коммиты и версии — только по явной команде.
6. «Раньше работало неплохо, кроме одного места» → восстановить хорошее
   поведение везде, исправить ТОЛЬКО названное плохое место.

## Форма ленты (уточняется пользователем; текущее понимание)

Лента — ОДИН замкнутый path: полоса над левой строкой → талия в коридоре →
полоса над правой строкой. Строковая часть — КОНЕЦ ЛЕНТЫ, не отдельная
заливка. Односторонний член — ОДИН path: полоса над строкой + язык в коридор
(не квадратик + отдельная заливка = порванная лента). Запрещены ОТДЕЛЬНЫЕ
заливки строк, живущие отдельно от ленты, и заливки строк вне цепочки.
Один тон всей ленты; hot — один оттенок на всю цепочку; подпись на плато;
талия сдвигает только середину; hover — одна цепочка.

## Запрет на слом

- Не удалять работающие механизмы ради «чистоты» — только по явному запросу.
- Любое изменение ribbon/ обязано оставлять `pnpm test` и `npx eslint .`
  зелёными, но зелёные тесты НЕ заменяют визуальное подтверждение пользователя.
- Если претензия кажется противоречащей правилам — сначала спросить
  пользователя, что именно на экране не так; не «чинить» удалением правил.
- Сборка при WIP пользователя: `git worktree add --detach /tmp/cd-rNN HEAD`,
  node_modules симлинком; dist/demo синхронизировать обратно (gitignored).
  Чужой WIP (surface/, geometry/, interface/, columns/Items.tsx) не коммитить.
